## Context

`RtComposite` 同时使用独立的 HDR 界面合成管线和按需创建的 SDR 呈现管线。它在图像重建前等待设备空闲并显式使绑定失效。世界光追一次可加载多个 raygen、miss 和 hit 阶段，覆盖层一次加载顶点和片元阶段。所有模块都来自同一资源路径。

## Goals / Non-Goals

缩小重复实现与依赖可见范围，保留公开方法、资源名称、绑定布局、调度和失效顺序。渲染算法、配置、原生库打包和其它渲染阶段的描述符设计不在本次范围内。

## Decisions

- 在公共的 rt 包集中处理 SPIR-V 读取和临时模块。创建管线时用 Java 资源作用域保证异常退出也能释放已经取得的模块。Vulkan 设备、模块和临时内存各有明确归属。
- 两个呈现入口使用同一份双图像计算管线实现，每个实例各自维护绑定缓存和 Vulkan 对象。显示映射与曝光拥有不同的绑定和常量布局，继续自行管理。
- 现有测试使用 Jupiter API 和引擎。分别声明编译 API 与运行引擎，沿用 JUnit BOM 和平台启动器。

## Risks / Trade-offs

句柄数值可能在图像重建后复用。保留强制失效路径，将既有回归检查延伸至共享实现。规范和源码检查能确认调用关系，实际画面与驱动行为需要在具备完整工具链的 Minecraft 客户端验证。
